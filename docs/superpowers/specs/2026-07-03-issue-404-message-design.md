# Issue/PR 404 提示优化设计

## 背景

Issue 截图查询当前把所有 HTTP 4xx/5xx 响应描述为暂时性页面加载失败。对于不存在或不可访问的 Issue/PR，GitHub 返回 HTTP 404，继续提示用户稍后重试会造成误导。

## 目标

- HTTP 404 使用明确提示：`该 Issue 或 PR 不存在，或当前无法访问。`
- 其他 HTTP 4xx/5xx 继续使用现有的暂时性错误提示。
- 页面关闭、停止截图等现有错误处理行为保持不变。

## 实现设计

在 `screenshotIssue` 检查响应状态时，先单独判断 404 并抛出对应错误，再由现有的通用 `status >= 400` 分支处理其他失败状态。调用方继续复用现有异常捕获及消息前缀，因此用户输入 `#999` 时会收到包含 Issue 编号和明确原因的完整提示。

不引入新的 GitHub API 请求，也不区分“确实不存在”和“因权限不可见”；GitHub 对私有或不可访问资源同样可能返回 404，因此文案同时涵盖这两种情况。

## 测试

- 新增回归测试，模拟页面返回 HTTP 404，断言错误包含新的不存在/不可访问提示，并确认不会截图且页面仍会关闭。
- 保留 HTTP 504 测试，证明其他服务端错误仍沿用原提示。
- 运行完整测试套件与 TypeScript 构建。
